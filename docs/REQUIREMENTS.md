## 一、用户原话（逐字保留）

> 我想要一个简单的personal app用来处理我自己的每日to-do，我想要有基础的云端同步，日期功能
> 服务器和数据库可以用vercel/mongodb处理，如果你有更好的推荐也行
> 我的使用场景：每天打开电脑，确认今日任务，同时阅览之后日期的任务（最好是月视图，因为我习惯apple的月视图），然后在月视图里可以直接点击加入新任务，也可以在下方输入框里填写任务，根据紧急程度自动配置到合适的日期，每天任务上限数量可以调整，可以根据我的判断锁定日期不再添加新任务，月视图里也可以直接点击任务用来标记完成。
> 需要可以同步apple calendar作为参考，但可以取消apple calendar的显示，从而不喧宾夺主。
> 样式要极简黑白无圆角，但保留拓展皮肤的可能性
> 你先存一个md文档用来保存我的原话，防止做偏了，接着再告诉我你计划使用的技术栈。

## 二、需求拆解（由原话推导，仅作实现参考）

### 2.1 定位
- 单人使用（personal app），非多租户产品。
- 核心是"每日 to-do"，不是项目管理工具。
- 简单优先：功能不外扩。

### 2.2 核心功能点
1. **云端同步（基础）**：多设备打开都是同一份数据；不要求实时协作、不要求离线冲突合并的复杂机制。
2. **日期功能**：任务归属到具体日期。
3. **月视图为主界面**：参照 Apple 日历的月视图习惯（整月网格、当日高亮、格内列事件）。
4. **月视图内直接建任务**：点击某一天的格子即可添加该日任务。
5. **底部输入框快速录入**：不指定日期，由系统**根据紧急程度自动分配到合适的日期**。
6. **每日任务上限可调**：上限是全局可配置的数值；自动分配需遵守该上限。
7. **锁定日期**：用户可手动把某天标记为"锁定"，之后自动分配不再往该日塞任务。
8. **月视图内直接点击任务标记完成**：一次点击完成/取消完成，不进详情页。
9. **今日任务确认**：每天打开时能第一眼看到今日任务。

### 2.3 Apple Calendar 集成
- 作用是**参考**，不是主角。
- 必须可以一键隐藏/关闭日历事件显示。
- 显示上要弱于 to-do（不喧宾夺主）。

### 2.4 视觉规范
- 极简、黑白。
- **无圆角**（border-radius: 0，全局）。
- 但结构上要预留换肤能力：颜色/字体等走 design token，后续可加主题而不重构。

## 三、已确认决策（2026-08-19，用户拍板）

| 项 | 决定 |
|---|---|
| 数据库 | **Neon Serverless Postgres + Drizzle ORM**（不用 MongoDB） |
| 紧急程度输入 | **输入框旁边一个三档选择器**，三档**用颜色区分**（不是文字标签） |
| Apple Calendar | **只读 .ics 订阅**，接受不能写回 |

## 四、总原则：能用样式说明的，不要文字说明

界面上任何状态优先靠**视觉编码**表达，禁止加解释性文案。具体落到：

- 紧急程度 → 色块 / 色条，**不写"高 中 低"**
- 已完成 → 删除线 + 降透明度，**不写"已完成"**
- 日期锁定 → 格子底纹（斜线）+ 加号入口消失，**不写"已锁定"**
- 今天 → 日号反白实心方块，**不写"今天"**
- 当日已满上限 → 格子边框加重 / 计数点满格，**不写"已满"**
- 非本月日期 → 降透明度，**不写任何提示**
- Apple 日历事件 → 细线条 + 低对比度，明显弱于 to-do

例外：空状态和错误提示可以有文字。

## 五、配色约束

黑白是**底色系统**，颜色**只用于紧急程度**这一个维度，是全局唯一的彩色信号，其他任何地方不得引入色相。三档色仍走 CSS 变量（`--p1` / `--p2` / `--p3`），换肤时可整组替换。
