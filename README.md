# 日程

单人用的个人管理台，两个页面：

- **日程** —— 每日 to-do。月视图 + 待办队列 + 右侧常驻科研项目面板，底部录入按紧急程度自动排期，Apple / Google 日历只读订阅作参考。
- **账簿** —— 收支分析。录入仍然在喵喵记账里做，这边接它导出的 CSV。

需求原文见 [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) —— 有分歧时以那份文档的第一部分为准。

## 技术栈

- Next.js 16（App Router）+ TypeScript
- Neon Serverless Postgres + Drizzle ORM
- 手写 CSS，无 UI 库；全部颜色走 CSS 变量，换肤只改 `src/app/globals.css` 顶部的令牌块
- 部署：Vercel

## 本地起步

1. `cp .env.example .env.local`，填入 Neon 连接串（Neon 控制台 → Connection string）。
2. `npx drizzle-kit push` 建表。
3. `npm run dev`。

`APP_PASSWORD` 留空时不开鉴权，适合本地；部署到 Vercel 时务必设上。

## 手机 / PWA

窄屏（≤700px）下分成两个 tab，顶栏左上角切换（横线 = 队列，九格 = 月视图，选中的那个反白）：

**队列 tab（默认）** —— 全屏，就是桌面左栏那份按日期 + 档位排好的未完成任务，手机上可以滚动看全部。日常打开看的就是这一屏。

**月视图 tab** —— 抄的是 iOS 日历的分工：上半屏网格，**一天只画一个点**，只回答「这天有没有事」，颜色取当天最急的那件，全做完了变空心；下半屏是**被点中那天的详情**，任务和日历事件都带文字，还有锁定开关和当日新建输入框。

之所以这么分：一格只有 50 来 px 宽，塞不下能读的文字。之前试过每件事画一个点，结果是密度低又点不动，等于装饰。让网格只管「哪天有事」、把密度放进下面的详情，网格才值得占那块地方。

触摸设备没有 hover 也没有右键：

| 手势 | 结果 |
|---|---|
| 点某天 | 选中，下面显示当天详情 |
| 长按格子 | 锁定 / 解锁该日（详情里也有个看得见的开关）|
| 长按任务行 | 出菜单（改优先级 / 截止日 / 删除）|
| 点任务文字 | 就地改名 |
| 点方框 | 切换完成 |

窄屏下不做拖动改日期（长按留给锁定和页面滚动），那件事在桌面上做。

针对 Safari 处理过的坑：`100dvh`（地址栏伸缩时 `100vh` 会把底栏顶出屏幕）、`env(safe-area-inset-*)` 让开刘海和 home indicator、输入框字号 16px（更小 iOS 会自动放大整页且退不回来）、`color-scheme` 让原生日期控件跟着主题走、关掉整页橡皮筋和点击高亮。

加到主屏后按独立 app 打开（`display: standalone`）。**iOS 的独立 app 有自己的存储容器，和 Safari 不共享 cookie**，所以第一次打开需要再输一次口令。

## 交互约定

| 操作 | 结果 |
|---|---|
| 点月视图格子空白处 | 就地新建当天任务 |
| 点格子里的任务 | 切换完成 |
| 长按任务拖到别的格子 | 改到那一天（锁定日不接受落点）|
| 右键任务 | 改优先级 / 记最晚完成日期 / 删除 |
| 点格子左上小方块 | 锁定 / 解锁该日 |
| 底部输入框回车 | 按紧急档自动排期；右边的日期填的是**最晚完成日期**，不是排在哪天 |
| 左侧队列点方框 | 切换完成（勾掉即从队列消失，月视图里还能找回）|
| 左侧队列点文字 | 就地改名 |
| 顶栏日历图标 | 显示 / 隐藏我的日历 |
| 顶栏双层日历图标 | 显示 / 隐藏他人日历 |
| 按 `t` | 跳回今天所在月份 |

状态一律靠样式表达：完成 = 删除线 + 淡化，锁定 = 斜线底纹，满额 = 边框加重，今天 = 反白方块，有最晚完成日期 = 右侧细线，晚了 = 右侧粗线并染上档位色。界面上不写这些状态的名字。

「晚了」有两种情况，视觉上不区分：计划日期越过了最晚完成日期，或者最晚完成日期已经过去而任务还没做完。

排期只决定任务先摆在哪一格，**它不是承诺**。真正要盯的是截止日：底部录入框右边填的就是它，左侧一览行尾显示的也是它。

## 左侧队列

显示**所有未完成**的任务，按日期、再按档位排序；换一天插一条分隔线，今天那批不用（上面的大日期已经说了）。

**不滚动，也不强行显示全部**——视窗放得下几条就显示几条，放不下的整行藏掉，不留半截被切开的文字。看不见的那几条到时候会自己滚上来。窗口变高就自动多显示几条。

队列内容与「当前翻到哪个月」无关：数据窗口固定向前覆盖半年，你翻到七月或十二月，队列显示的都还是同一批欠账。

## 每天打开时的顺延

打开应用会先把**过期且未完成**的任务顺延到今天，然后才渲染。已完成的留在原处，它们是那天的记录；未来的不动。

规则本身是「当日没完成就移到下一天」，每天反复应用的不动点就是「全部落到今天」——隔了几天没开电脑，一天一天推也还是推到今天，所以直接一次推到位。顺延不看每日上限，也不看锁定：那两条约束管的是**新任务往哪放**，不是把已有的任务丢掉。

## 自动排期规则

按底部选中的档位决定落点，规则刻意保持可预测：

- **第一档**：落今天，无视每日上限；今天若被锁定则顺延到最近的未锁定日。
- **第二档**：从今天起，第一个「未锁定且未满」的日子。
- **第三档**：从明天起，第一个「未锁定且未满」的日子，不占今天的名额。

上限只统计**未完成**的任务。

**最晚完成日期是排期的硬上限**：排期绝不越过它。截止日之前没空位就直接钉在截止日当天并允许超限——排到截止日之后的话，任务一落地就会被标成「晚了」，那是自相矛盾的。所以「三档 + 截止今天」会落今天，不会按三档的常规从明天开始找。

截止日本身已经过去的任务放今天（最早的可能），并如实显示成「晚了」。

## 日历订阅

分两组，各自独立开关：**我的日历** 和 **他人日历**（家人等）。两组都是一行一个地址，可以填多个。

- **Apple**：Mac 日历 → 右键目标日历 → 共享设置 → 勾选「公开日历」→ 复制链接
- **Google**：设置 → 选中该日历 → 「日历的秘密地址（iCal 格式）」

他人日历只需要对方把链接给你，不涉及授权，两边都是只读。月视图里他人的事件左边那道线是**点线**，自己的是实线，其余样式完全一样。

两组一次拉完、都带来源标记，显示与否在前端过滤 —— 所以开关是即时的，藏起来时设置面板里也照样能看到源还通不通。设置面板里的 `3/3` 表示三个源都拉通了，数字变红说明有源挂了。

只读订阅，服务端缓存 15 分钟，一个源失败不影响其他源，本 app 不会写回你的日历。

时区：事件时间按**浏览器所在时区**换算后显示。日历里混着不同 TZID（东京、上海）也不会错位，服务端自己的时区（Vercel 上是 UTC）不参与计算。

# 账簿

从 `Yanlin's Account Book 2024-2026.xlsx` 移植而来。原来 Excel 里 `Raw` 之下全是公式，这里只存 `Raw` 对应的原始字段，**分组、汇率换算、年度透视、Overview、净值一律算出来，不落库** —— 想改一个数就去改流水或映射，跟原来的规矩一样。

## 数据流

录入在**喵喵记账**里做，导出 CSV（`分类,时间,金额,账户,账本,货币,备注`）后在账簿页点「导入 CSV」。

导出区间会重叠，所以导入是**幂等**的：`transactions` 上有一条 (分类, 时间, 金额, 货币, 备注) 的唯一索引，重复的直接跳过，导入结果会告诉你新增几条、跳过几条。

**不落指纹列**：那样「怎么算指纹」会变成第二份真相，换个语言算一遍就对不上（第一版就踩了这个坑）。

## 分组与目标

五组：Income / Needs（≤60%）/ Wants（≤10%）/ Investment（≥30%）/ Family & Gifts（无目标）。每个喵喵分类必须映射到唯一的 (Group, Detail)。

新分类出现时，账簿页顶部会红字列出来 —— **没映射的钱不会出现在任何一张表里**，所以那里直接给了补映射的入口。

## 几条从 guideline 继承的判断

- **NISA 是投资，不是花掉了**：它在 SPENDING TOTAL 里算流出（于是 SAVINGS = 银行账户的变化），净值表再把它加回投资账户。NET WORTH = 银行 + 投资。
- **借出**是会回来的钱，还回来时记作收款；不要去"修正"这个不对称。
- **支出为负、收入为正**，跟喵喵导出的一样。`SAVINGS = 收入合计 + 支出合计`。
- `-0.01` 这类占位金额和它的备注是有意的记录，别清理。
- 汇率是**固定近似值**，不是实时价，只在明确要求时改。

## 时间戳

`occurred_at` 是无时区时间戳，存的就是喵喵导出的墙上时间。读取时**在 SQL 里 `to_char` 成文本**，不让驱动还原成 `Date` —— 那样就得选「按本地还是按 UTC 取值」，而这两种在开发机（JST）和 Vercel（UTC）上给的答案不一样。墙上时间全程不经过 `Date`，就没有这个问题。

## 移植时的核对

历史 1103 笔一次性导入后，拿 xlsx 里已算好的值逐格对过：三年的每个 Detail × 12 个月、三个合计行、净值 30 个月 × 5 个字段 —— **0 处不一致**。
